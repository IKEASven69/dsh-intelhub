### 1.2 Agent 消费 · dsh 会话真调 memory_recall（MiniMax M3 驱动）

- 场景：dsh web（8186）新会话，默认模型 MiniMax M3 (Token Plan)，指令"用 memory_recall 查 q='暗号 紫色河马'"。
- 结果：工具真实调用（Tool call memory_recall），**原文逐字召回**："决定：我们的暗号是紫色河马"（[decision]，来源 zcode，2026-8-23）。
- 质量亮点：agent 自主批判召回质量——指出一条候选被截断在标题、一条"深夜干活"49% 弱相关不在命中；页脚实测 1 轮 2 步 · LLM 8.8s · 工具调用 6s · 输入 29.7K tok。
- 对照（修复前）：同场景 4 天前因 ollama 本地模型挂起 3 分 12 秒无响应（旧截图存证）——切 minimax 后闭环。
- 截图：`shots/t2-agent-consume.png`。

### 1.2+ 自然语言场景 · 用户不提工具名（2026-09-03 补，冷神质询后）

冷神指出上轮 1.2 是"开发者测接口"（指令里带了工具名），不是用户场景。补真实场景测试：

- **用户原话**（新会话，零工具名）："咱们的暗号是什么来着？我忘了"
- **agent 行为**：自主调用 memory_recall（query 自动取"暗号 紫色河马"）→ 命中原文 → 回答
- **回答**："决定：我们的暗号是紫色河马"（[decision]，来源 zcode，2026-8-23），并附召回质量自查
- **追问复用**：再问同题时 agent 正确不重复调工具（"already retrieved in previous turn"），3 秒直接答
- 性能：首响 15s（含工具调用）· 追问 3s · 缓存命中 41%
- 结论：**工具描述 + 提示注入足以让 agent 自主判断何时查记忆**——用户零学习成本。
- 截图：`shots/t4-natural-question.png`

## 三、测试抓出并修复的真实 bug
