## 〇、v2 修订——两层记忆模型(2026-08-22,openhanako 对照讨论定稿)

> v1(一~五节)= 中心蒸馏全量事件、单一共享库。v2 改两层,中心减负。改动依据与完整论证见 `../../docs/memory-architecture.md`。

**架构改动:**
1. **L1 成员私有记忆**:每个成员只蒸馏自己的 reply/任务经历(per-agent scope,复用 hippo 引擎的 project 机制)。各写各的——授权边界、写入竞争、角色专长三个 v1 隐患一并消失。参照 openhanako"每 agent 独立记忆 + Agent 即文件夹";私有记忆按文件夹组织,支持成员退役归档(私有归档,已晋升的团队记忆保留)。
2. **L2 团队共享记忆 + 晋升机制**:中心任务从"全量蒸馏所有事件"减为两件——**晋升判定**(≥2 条私有记忆语义互为印证 → 合并成团队记忆,derivedFrom 带多条源链;判定标准同 knowledge-base 的联合提炼判定,"一个坑被 ≥2 人独立踩到"是最硬团队级信号)与**总结**(跨成员协作模式,LLM)。
3. **读侧注入**:成员私有 Top-K + 团队 pinned 约束(≤3 条,防上下文污染)。

**引擎侧定稿(搬 hippo-skills 现成件):**
4. 质量门:top-N=20 截断;三档去重(≥0.93 reinforce / 0.8–0.93 maybe 永不自动落库 / <0.8 new);工具/任务失败=高可信 lesson 信号。
5. 存储:append-only JSONL 事件账本为真相源(退役=retire 事件带 supersededBy,fold 过滤当前视图——并发免锁、审计免费);sqlite+vec 只做查询层;MD 频道投影=可再生视图;L0 原始事件 90 天滚动窗口(蒸馏产物已带 derivedFrom 摘要)。
6. 衰减:类型基线 τ × 用户白名单(决策/约束类永不衰减,只接受矛盾检测)× strength 访问强化(recall 命中 +1、log1p 加权)——白名单=静态先验,strength=动态后验,互补。
7. **refiner/LLM 决策**:五分类(闲聊|事实|决策|约束|需求)是语义任务,正则不可为;但 T1 留空 refiner 钩子先跑,T2/T4 用真实团队数据对比记忆质量后再决定接入——LLM 被证据拉进来,不预埋。

**退役三级分流**(替代 v1 单一审批门;按"忘掉的错误成本"分级,防审批疲劳):

| 条目 | 处理 |
|---|---|
| 闲聊 / 已被取代 | 自动退役(derivedFrom 链保留) |
| 决策/约束到期(白名单除外) | 审批队列:面板批量,附最后访问/引用数/来源链 |
| 被矛盾推翻 / 调研过期 | 退役提案附证据 → 聚合进周期报告 |

**职责切分**:蒸馏=引擎逐条提炼,记"知道了什么"(事件驱动);总结=中心跨事件归纳,记"我们怎么协作"(周期,LLM 刚需——分工模式/瓶颈不存在于任何单条事件)。总结是预判卡的原料供给。

**里程碑影响**:T0 不变;T1=蒸馏管线+账本+per-agent scope;T2=面板+退役审批门+**晋升队列**;T3 不变;T4=四步循环+(refiner 接入决策点)。

## 一、依据(为什么是这个位子)

1. **上游有地基、无记忆**:rc.8 把实验性 Agent Teams 收进核心(持久 mailbox `quiet|wakeup` 投递、共享任务 DAG `blockedBy`/`revision` CAS/`writeScopes`、事件溯源回放 `foldTeam()`)——协调正确性已解决,但**成员干完活,经历就散掉了**,没有任何沉淀机制。
2. **记忆类插件全是单人视角**:77 个记忆插件(含两个两万星巨头)均无"团队共享记忆"概念;社区 dsh-agent-teams 插件 499→730⭐(一周),需求被验证。
3. **openhanako 的参照验证**(`_ref/openhanako` 源码已读):其频道系统(bookmark 游标 token 经济、**reply 才写记忆摘要**、MD 文件即人类可读投影、随机点醒主动发言)用 ~1400 行实现完整循环,验证了"说话才入记忆"与"可读投影"两个关键设计;但文件锁仅进程内、无任务依赖、无冲突防护——**生活流最优,工作流不足**。

## 二、架构(三层杂交:agent-team 的正确性 × openhanako 的可读性 × hippo 的记忆模型)

```
① 事件源(只读消费)
   agent-team: TeamMessageSnapshot / TeamTaskSnapshot 事件流
   ——事件溯源/CAS/writeScopes,并发正确性由上游保证
        │ ② 蒸馏(本插件核心)
        ▼
   reply 消息 / 任务完成事件 → distill → 共享记忆库
   记忆带:类型(闲聊|事实|决策|约束|需求)、时间戳、来源事件链(derivedFrom)
   分级寿命:遗忘曲线衰减(τ 按类型) / 长期保留
   退役而非删除:supersededBy + 更改原因,可审计(每条团队信念可溯源)
        │ ③ 投影(两种视图)
        ▼
   频道式 Markdown 导出(人类可读,openhanako 式"文件即真相")
   设置面板:团队记忆列表 / 类型与强度 / 退役审批门 / 团队任务 DAG 可视(flowloom canvas 候选)
```

**团队版自我进化循环**(复用《dsh-hippo桥-方案文档》四·二):
- **总结**:每团队周期把 mailbox+任务事件合成团队级洞察("这类任务我们上次怎么分工的");
- **调研**:外部事实类团队记忆 web 复核,过期→退役提案附证据;
- **预测**:基于团队 patterns 生成"下一步预判卡",新任务开场注入;
- **自退役**:衰减/被矛盾/过期 → 退役候选队列,面板一键审批。

## 三、里程碑

| # | 内容 | 验收 |
|---|---|---|
| **T0** | 骨架 + agent-team 事件读取:拉取一支团队的 mailbox/任务事件流 dump 成 JSON | 能完整导出一个真实团队的全部事件 |
| **T1** | 蒸馏管线:reply 消息与任务完成事件 → distill → 记忆事件(带类型/来源链) | 团队跑一轮任务后,记忆库出现带溯源的可检索条目 |
| **T2** | 面板:团队记忆列表/搜索/类型与强度/退役审批 | 面板能审批一条退役并看到理由链 |
| **T3** | 频道式 MD 投影导出 | 导出的 MD 打开即完整可读的团队协作记录 |
| **T4** | 团队自我进化循环(总结/调研/预测/自退役) | 跑通一个完整周期 |
| **T5** | 发布(MIT → awesome-dsh-plugin 收录 → dsh-market) | 收录通过 |

## 五、与既有项目的关系

- **dsh-hippo**:共用引擎与自我进化循环——team-memory 是"团队版入口",hippo 是"个人版入口";
- **flowloom**:团队任务 DAG + mailbox 的可视化面板是其 canvas 技术的天然用武之地(候选,不强绑定);
- **depsec**:自退役的"证据链"哲学同源(审计性);
- **openhanako**(v2 增):L1 私有层与"Agent 即文件夹"的参照(公开项目,非依赖);其无共享层,即 L2 的定位;
- **knowledge-base**(v2 增):晋升链顶层——团队记忆的 patterns/联合提炼出口指向 KB 的 insights/skills(人类把关终库);插件永不直写 KB,边界见 `../../docs/memory-architecture.md` §五。
