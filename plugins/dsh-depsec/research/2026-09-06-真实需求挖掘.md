## 用户原话（pnpm #9326，8 评）

1. "This sort of thing is annoying and **people always look to disable them**" —— 用户的第一反应是关掉安全特性
2. "**I rolled back to v9.15.9**. Not going to update unless the default changes. **I'll move away if no other way**." —— 痛到回退版本、威胁迁移
3. Railway 工程师（railpack 作者）："**How can we disable approval in a CI environment without editing code files?**" —— CI/自动化场景无法交互式审批
4. 相关 issue：#8958（mute 警告的诉求）、#12572（37 评，其他包管理器来抄 approve-builds）、#12982（allowBuilds 写入时机 bug）

## 官方解法的缺口

pnpm v10.9 的回应是 `dangerouslyAllowAllBuilds` —— **全放，名字自带 dangerously**。
用户手里的选项只有两个极端：逐个 approve（烦） vs 全部危险放行（不安全）。
**中间态——「基于证据的安全自动放行」——官方没做，这就是空缺的精确形状。**

## 发布叙事重写（对标用户原话）

不再讲"安全审计工具"，讲 **ERR_PNPM_IGNORED_BUILDS 的解药**：
pnpm 把选择权还给你时只给了两个极端；trust-list 替你读完每一行脚本，
证据 PASS 的自动安全放行，可疑的留下等你点头。
目标受众第一名不是"安全爱好者"，是**每个被 Ignored build scripts 警告烦到的人**（163 个 issue 的作者们）。
