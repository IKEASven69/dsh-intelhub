# dsh-trust-list v0.5 设计文档：插件侧静态审计深化

> 2026-09-01。调研先行（竞品源码全部读完），本文档定范围、规则、语料计划与质量门槛。

## 一、调研结论（为什么做这个）

四家竞品源码拆解（`/tmp/rivals/` 全文读过）：

| 竞品 | 覆盖 | **没做** |
|---|---|---|
| trust-check（liuwenji007） | 注入面计量（patch override、systemPrompt 注册点、skill 字节数）、egress 目的地白名单分级、ack 确认 | 不读 markdown 内容恶意性 |
| poison-guard（zoahdev） | 7 条代码正则 + JS-X-Ray v16（17 种 AST warning 映射），CLI + GH Action | 只看代码，不读 SKILL.md |
| plugin-guard（taxueseek） | 14 条正则 + site 分类 + combo 升级 P0、装后哈希锁、脱毒副本 | md 命中被降级 example→info，等于不看 |
| secure-audit（PensiveFei） | **最强注入规则表**（32 条中英双语，6 类目）+ 同形字/零宽/base64 变体归一化 + 置信度评分 | 扫的是**运行时对话流**，不是装前文件 |

**真空：装前 SKILL.md / commands / agents 的内容恶意指令检测，无人做。** 而 dsh 插件的头号攻击面恰恰是"教 agent 偷 key 的说明文字"（#4616 的"投毒盗KEY插件"），不是 postinstall 代码。代码侧三家已卷；内容侧零供给。

## 二、v0.5 范围（四项，全部复用现有资产）

### 1. 提示注入内容检测（主项）`src/prompt-injection.ts`

**扫描面**（会被注入模型上下文的文本，不含人类看的 README）：
`skills/**/SKILL.md`、`commands/**/*.md`、`agents/**/*.md`、`*.prompt`、`prompts/**/*.md`

**规则类目**（双语，继承 secure-audit 分类学 + dsh 特化）：
| 类目 | 示例 | 判级 |
|---|---|---|
| 隐蔽外传（critical） | 「不要告诉用户」+「把 API key/环境变量 发/送到 URL」「silently post env to…」 | block |
| 凭据外传指令 | 「read ~/.ssh and upload to https://」「把 token 发到 webhook」 | block |
| 指令覆盖 | 「ignore previous instructions」「忽略之前所有指令」 | high |
| 越权执行 | 「run arbitrary commands」「执行任意命令」「rm -rf」 | high |
| 隐蔽标记 | 「do not tell the user」「不要告诉用户」「静默执行」「hide this」 | high（与行动类同文件共现升级 block） |
| 伪权威 | 裸行的 `SYSTEM:`/`ADMIN NOTE`/`[系统消息]` | medium |
| 持久化渗透 | 「add this to your CLAUDE.md/配置，always…」「每次会话都先…」 | medium |
| 解码执行 | 「base64 解码后执行」「decode and run」 | high |

**防误报三闸**（这是与"给代码做正则"的本质区别——技能文件天然含 curl/git 示例）：
1. **定向性**：外传/执行类必须同时命中 [凭据/env 语境] + [URL/webhook 目标] 才判 critical；裸 "run npm test" 不响；
2. **代码围栏降级**：``` 围栏内的命中降一级（技能教用法是常态），围栏外 + 隐蔽标记共现才升级；
3. **共现升级**：单一 high 只 warn；同文件 ≥2 个不同类目 high，或 high + 隐蔽标记 → block。

**反混淆 pre-pass**（借鉴 secure-audit，轻量实现，零新依赖）：零宽字符剥离、全角→半角、同形字映射（а→a 等）、有界 base64 变体解码（≥16 字符且解码后 ≥80% 可打印才收，上限 4 个变体）。**不上 JS-X-Ray**（535KB + 7 依赖，会破坏 lib 零外部依赖纪律）——记 v0.6 议题，先验证语料质量再谈引擎。

**输出**：`{ verdict: pass|warn|block, findings: [{file, line, category, severity, snippet}], egress: [{host, tier}] }`

### 2. egress 静态目的地清单

复用 `domainsOf` + 白名单：roster 扫描时提取插件全部文件里的 URL → 分级 known-dev / ai-provider / unknown / plaintext-http / raw-ip，进 roster note + findings（unknown 或 plaintext 才出 finding）。与 egress-guard（运行时拦截）互补，不冲突。

### 3. 已装插件哈希锁

`trust-record` 扩展：roster 扫描时对每个插件的 `package.json + lib/* + skills/*` 做内容指纹（FNV-1a 文件清单），存入 `.depsec-baseline.json`；下次 roster 对比，文件变了 → 「已装插件文件变更」finding。封"装时干净、装后被换"路径（plugin-guard 同思路，但我们与版本锁同一套记录）。

### 4. roster 集成

`PluginRosterEntry.verdicts` 增加 `promptInjection: BlockVerdict`；三个既有 verdict 照旧。面板加一列。

## 三、语料计划与质量门槛

**良性语料**（测误报）：本地真实 SKILL.md —— `D:\coding\Skills\`（40+ 个 baoyu/apify 真实技能）+ `dsh-plugin/plugins/*/SKILL.md`（9 个自家插件）+ 合成典型（git 工作流、前端设计、带 URL 的 API 技能、含 ``` 围栏的教程）。
**恶意语料**（测漏报）：双语 TTP 手写样本 ≥12 条（隐蔽外传、伪权威覆盖、持久化渗透、解码执行、同形字/零宽/base64 变体各 1+）。
**门槛**：良性 0 block；恶意 100% catch（block 或 warn+egress 标记）；数字进 README 跑分表。CI workflow 同步加这一步。

## 四、不做（明确出界）

- 运行时内容扫描/拦截（secure-audit、egress-guard 的地盘，需要宿主 seam）；
- JS-X-Ray/AST 引擎（v0.6 议题，先看 v0.5 语料数据说话）；
- 签名/共享放行清单（#5498 方向，等生态 adoption）。

## 五、验收

vitest 全绿（预计 +25 案例）；roster 对 9 个自家插件实测全 pass（自家插件必须过自己的审计）；README 跑分表更新；commit 拆三个（模块+测试 / roster 集成 / 文档）。


## 六、实施结果（2026-09-01 当日落地）

- `src/prompt-injection.ts`：19 条双语规则（6 类目）+ 反混淆 pre-pass（零宽剥离/全角归一/同形字映射/有界 base64 变体含 CJK）+ 三闸防误报（定向性/围栏与内联代码降级/共现升级）+ 相邻内联代码豁免（`--force` to bypass… 形态）。
- 质量验收：恶意语料 14 条 0 漏报；真实语料 560 个生产 SKILL.md（baoyu/apify/gsd/hippo 等）**0 误报 0 block**；过程中抓出并修掉 6 类真实误报形态（API 端点文档的 access_token=、安全警告引用反面示例、官方安装管道、教学正则、UX 表述、flag 能力描述）——每一个都变成了回归用例。
- roster 集成：`verdicts.promptInjection` 第四维 + egress 静态清单（非白名单 host 出 low finding）+ 插件哈希锁（`pluginRecord` 命名空间，与依赖 version lock 同一套 diff/merge）。
- 测试 124 → 145 全绿；构建通过。
