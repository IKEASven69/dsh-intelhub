# dsh-trust-list 判定质量调研报告

> 2026-08-29。方法：拉取 npm 人气 top 1814 包的 install 生命周期脚本（446 条 / 384 包，`research/corpus.json`），
> 全量过 `analyzeInstallScript`（`research/results.json`），再用 9 种真实投毒 TTP 做漏报探针（`research/probe-evasion.mjs`）。

## 一、总评

**红线精度高（0 误拦截），黄线召回灾难（75% 误警告）。**

| 指标 | 数值 | 评价 |
|---|---|---|
| pass | 112 (25%) | — |
| warn | 334 (75%) | **告警疲劳风险：全网最健康的包群 3/4 被警告** |
| block | 0 | 好消息：红线模式在头部包上零误报 |
| TTP 漏报 | 4/9 | 见下 |

WARN 的三大构成：
1. **"未能识别的命令" 302 条（90%）**——不是恶意，是白名单太窄。聚类结果：
   - 包管理器脚本委派 ~170：`npm run` ×121、`yarn run` ×41、`pnpm/bun run` ×8
   - 标准 build 工具 ~100：`shx tsc rollup gulp make tsup babel tsup cross-env rimraf npm-run-all/run-s dumi bob tshy pkgroll`
   - 发布门控助手 ~70：`not-in-publish in-publish npmignore skip-local-postinstall`
2. **"引用脚本未能读取" ~25 条**——语料没有 tarball 的伪影，真实安装时 host 能读到（esbuild/sharp 形态已测过为 pass），非缺陷。
3. `node -e` 内联 ~4 条——es5-ext 这类良性 try/catch require。

## 二、漏报探针（9 种 TTP，漏 4）

| # | 手法 | 现判 | 应为 | 根因 |
|---|---|---|---|---|
| 1 | `node -e` + `Buffer.from(hex)` + eval | warn | block | **-e 内联载荷完全不深挖** |
| 2 | `node -e` + child_process + 拼接域名 | warn | block | 同上 |
| 6 | `node -e` 读 Chrome `Login Data` | warn | block | 同上 + 敏感路径正则缺 Chrome 路径 |
| 7 | `curl -o X && chmod +x X && ./X` | warn | block* | "下载后执行"链无规则（*或至少重黄） |

已正确拦截：env 拼 GET URL、certutil 落盘、PS WebClient 到裸 IP、变量化 `~/.ssh` 外传、文件层裸 IP 外传。

**核心发现：漏报高度集中在"node -e 的引号内内容从未被检查"这一处。** 现在的文件层只查 `node file.js` 引用的文件，不看 `-e` 的字符串——而 -e 恰是投毒最爱的单文件自包含形态。

## 三、修复建议（按优先级）

1. **P0 — 深挖 `node -e/--eval` 与 `python -c` 的内联载荷**：提取引号内字符串，复用文件层规则（eval/new Function、child_process、超长 base64/hex、敏感路径、env+POST）。预计 1/2/6 全部转 block。
2. **P0 — 识别标准工具链，消灭 90% 的伪黄**：
   - 包管理器委派 `npm|yarn|pnpm|bun run <script>` → 绿"调用包内脚本 x（host 可递归解析）"，host 侧已有读文件机制，真实安装时可递归分析目标 script；
   - build/发布工具白名单（shx/tsc/rollup/gulp/make/tsup/babel/cross-env/rimraf/npm-run-all/dumi/bob/tshy/pkgroll/not-in-publish/in-publish/npmignore/skip-local-postinstall…）→ 绿"标准构建/发布工具链"；
   - `npx <pkg>` 保持黄（下载并执行远端，是真实投毒向量）。
   - 预期 warn 率从 75% 降到 ~15%。
3. **P1 — SENSITIVE_PATH_RE 补浏览器凭据路径**：`Login Data`、`User Data.{0,40}(Cookies|Local State)`、`AppData.{0,40}Cookies`。
4. **P1 — "下载后执行"链**：`(curl|wget)[^\n]*-o\s+\S+.*&&.*(chmod \+x|\./|\bash )` → 红"下载文件后提权执行"。
5. **P2 — 混淆特征**：`Buffer.from\([^)]+,\s*['"](hex|base64)['"]\)` 邻近 eval/exec → 红混淆载荷。

## 四、新增测试用例清单（修复验收标准）

误报侧（应 pass）：`npm run compile` / `yarn run build` / `shx cp README.md .` / `tsc && npm run test` / `not-in-publish || npm run prepublishOnly` / `npmignore --auto`。
漏报侧（应 block）：探针 #1 #2 #6 #7 原文。
边界（不应回归）：es5-ext 的 `node -e "try{require('./_postinstall')}catch(e){}" || exit 0` 应保持 warn（良性 -e 但引用本地文件，可递归解析后转 pass）。

## 六、修复结果（2026-08-31 已落地）

全部五项修复已实现并通过验收，测试 35 → 115（含另一会话新增的 typosquat/写回测试文件）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 语料判定 | pass 25% / warn 75% / block 0 | **pass 91% / warn 9% / block 0** |
| 漏报探针（9 种 TTP） | 拦 5 漏 4 | **拦 9 漏 0** |
| 误拦截 | 0 | 0（保持） |

落地内容：
1. ✅ P0 内联载荷深挖：`node -e`/`python -c` 引号内容按文件层规则分析；无实质内容的载荷（如 `"x"`）保持保守黄线，不冒充看懂（兼顾 edge-cases 语义）。
2. ✅ P0 工具链识别：`npm run`/`yarn build`/`pnpm test` 委派 + 30+ build/发布工具白名单 → 绿信号；`npx` 保持黄（下载执行远端包，有意保守）。
3. ✅ P1 敏感路径补 `Login Data` / `Chrome...User Data`。
4. ✅ P1 下载后执行链：fetcher `-o` 落盘 + 同文件 `chmod +x`/执行 → 红。
5. ✅ P2 混淆特征：hex 串 + `Buffer.from(...,'hex')` → 红；子进程+网络但零可识别域名 → 红（拼接/混淆特征）。

剩余 9% warn 构成：30 条是语料离线读不到包内 .js 的伪影（真实安装时 host 能读到并递归判定）、2 条 npx 有意保守、其余为真正的长尾未知命令（`ts-scripts install`、`npm install --prefix` 等，保守留黄合理）。
