一页看懂 dsh 插件开发：从零到上架的五步工作流

deck 自媒体台 · 2026-08-25 · 阅读 4 分钟

dsh 插件不是黑魔法。它是一个「两半结构」：host 半在 Node 里跑路由和文件系统，client 半是一个静态 js 文件，注入到你的侧边栏里。

插件的全部秘密就一句话：host 能做任何 Node 能做的事，client 能画任何 React 能画的界面。

第一半是 webServer。你注册路由、校验来源、读写文件——沙箱限制对它不生效，因为它本来就在你的机器上。第二半是 window.__ModuleLoader__.load()，一个静态文件，声明自己要什么座位：侧边栏、覆盖层，或者对话区。

五步工作流：脚手架 → host 路由 → client 注槽 → profile 接入 → 浏览器回归。每一步都有先例可抄，每个坑都有人踩过——比如 tsdown 会把某个路由的函数体整个摇掉，比如 cordis 的服务必须先声明 inject。

剩下的交给协议：TASK.md 一张任务卡，agent 干活，RESULT.md 交卷，你勾选落库。一周，你也能做出来。
