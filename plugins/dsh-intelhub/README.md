# dsh-intelhub

**第一个 zvec 原生知识库插件** —— 把你的文档变成 agent 的外挂大脑:拖入文件或整个文件夹,agent 获得**语义 + 关键词混合检索**能力,结果自带来源。

> 零守护进程 · 零 API key · 文档不出本机

## 为什么需要它

dsh 里已有的知识库插件只会**关键词检索**(SQLite FTS5)。但真实场景里,你记得文档写过什么,却想不起原话:

| 你问 agent | 文档里实际写的 | 关键词检索 | dsh-intelhub |
|---|---|---|---|
| "怎么配置超时时间" | "若对端 30 秒内无响应,会话将被中断" | ✗ 零词汇重叠,查无此物 | ✓ 语义命中 |
| "买了东西想把钱要回来" | "七日内可联系客服发起退货,款项原路退回" | ✗ | ✓ 命中 |
| "线上出问题怎么恢复" | "回滚到上一个稳定版本" | ✗ | ✓ 命中 |

而这一切在**本地**完成:33MB 的 multilingual-e5 向量模型 + 阿里开源的 [zvec](https://github.com/alibaba/zvec)(15k⭐ 进程内向量数据库)进程内嵌入——不需要像 hindsight 那样管理守护进程,不需要像云 RAG 那样配 API key、上传文档。

## 用户故事

| 场景 | 做法 |
|---|---|
| "把 `D:\docs` 喂给你,以后公司制度的问题先查它" | agent 调 `kb_import` 递归导入;此后相关提问先 `kb_search`,答案带 `文件路径#块号` |
| "这份 PDF 手册里,退货政策是什么?" | 拖入 PDF → agent 检索 → 引用具体段落回答 |
| "我的笔记里记过这个坑吗" | `kb_search` 按意思找,不要求你记得原话 |
| 文档更新了 | 重新导入同一文件夹即可——内容哈希去重,只重建变更文件 |

## 六个工具,一个知识库

- **kb_import** — 文件/整个文件夹导入(md / txt / pdf / docx / json / yaml / 代码等),后台建索引,逐文件可见;**Obsidian 库直接指库目录**(自动跳过 `.obsidian` 内部文件)
- **kb_import_url** — 网页存档:抓正文 → 入库,来源显示为 URL(调研攒链接场景)
- **kb_note** — 直接写文本:对话里的长文、agent 的调研结论、其他工具抓到的社交内容(微博/知乎……)
- **kb_search** — 语义+关键词混合检索(RRF 排名融合),精确标识符照样命中,结果带 `来源#块号`
- **kb_list / kb_delete** — 来源管理与移除(只删索引,不动原文件)

**任何来源 → 一个知识库**:本地文件夹、Obsidian、网页链接、对话长文、社交内容(经 opencli 类工具抓取后 `kb_note` 入库,覆盖 170+ 站点)、Notion/语雀导出的 Markdown——全部进入同一条 分块→向量化→混合检索 管线。

另有设置面板「本地知识库」:**拖拽上传**、路径导入、索引进度、检索预览、文件管理,以及空态**30 秒演示**(导入样例手册,并排展示关键词检索找不到 vs 语义检索命中)。

## 安装

```sh
dsh plugin add dsh-intelhub
```

首次导入时自动下载本地模型(约 30MB)到 `~/.dsh/dsh-intelhub/`,之后全程离线。

## 与同类插件的差别

| | dsh-intelhub | dsh-knowledge-base / dsh-knowledge | knowlp-rag | hindsight / ReMe |
|---|---|---|---|---|
| 检索方式 | **语义 + 关键词混合** | 仅关键词(FTS5) | 含向量 | 语义(记忆向) |
| 额外进程/服务 | **无**(zvec 进程内) | 无 | Python + 30s 引导 | 需守护进程/HTTP 服务 |
| API key / 上云 | **不需要** | 不需要 | 不需要 | 部分需要 |
| 定位 | 文档知识库 | 文档知识库 | 笔记知识图谱 | 对话记忆(互补不冲突) |

## 质量基准(可复现)

真实文档语料 + 换说法陷阱查询集(关键词零重叠),本地 e5-small(q8)模型:

- 命中@1:**6/7**,命中@3:**7/7**(同类关键词检索在同集上约 3/7)
- 诚实说明:最难的一条("配置超时" vs"回滚"这类运维近邻概念)33M 本地模型的余弦区分度为零;若你的场景对极致召回敏感,嵌入层可配置升级(存储层与向量层解耦)

## 架构

```
文件/文件夹 → 抽取(md/txt/pdf/docx)→ 分块(标题边界,120~400字)
  → 本地向量化(e5-small,嵌入用去语法文本)→ zvec 进程内存储(WAL 持久化)
  → 检索:向量腿 + jieba FTS 腿 → RRF 排名融合 → 带来源返回
```

- 增量导入:内容哈希去重,变更文件自动重建
- 模型未就绪时自动退化为纯关键词检索,不会失败
- 全链路在 dsh 插件进程内,无任何守护进程
